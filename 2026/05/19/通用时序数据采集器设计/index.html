1 概述

1.1 编写目的

本设计说明书为通用时序数据采集器（以下简称”采集器”）提供完整的软件架构与模块设计方案，指导开发团队进行系统实现，同时为二次开发者和插件开发者提供技术参考。

1.2 软件定位

采集器是一款面向工业物联网、能源管理、环境监测、设备运维等领域的通用时序数据采集与分发平台。其核心价值在于：

  • 通用性：屏蔽底层协议差异，以统一模型接入异构数据源
  • 插件化：驱动、存储、转发、告警均以插件形式加载，按需组合
  • 可扩展：提供完整SDK，支持第三方二次开发和自定义驱动编写
  • 高可靠：断点续采、断网缓存、数据溯源，确保时序数据零丢失

1.3 术语与缩略语

术语 说明
测点（Point） 最小时序数据采集单元，对应一个物理量或状态量
采集链路（Link） 从数据源到存储/转发的完整数据通路
驱动插件（Driver Plugin） 实现特定协议/数据源接入的可插拔模块
存储插件（Storage Plugin） 实现特定存储引擎写入的可插拔模块
转发插件（Forward Plugin） 实现特定目标系统数据分发的可插拔模块
告警插件（Alert Plugin） 实现特定告警检测与推送逻辑的可插拔模块
采集模板（Template） 可复用的测点配置与采集参数集合
SDK 二次开发工具包，提供API与脚手架

2 设计目标与原则

2.1 设计目标

维度 目标
接入能力 支持 8+ 工业协议、6+ 数据库、4+ 文件格式，插件可扩展
采集性能 单节点 ≥10 万测点并发采集，采集周期精度 ±10ms
存储吞吐 本地缓存写入 ≥5 万点/秒，时序库写入 ≥3 万点/秒
转发能力 并行转发目标 ≥8 路，消息队列吞吐 ≥2 万条/秒
可靠性 断网数据零丢失，恢复后 100% 补传
可用性 图形化组态配置，5 分钟完成新设备接入

2.2 设计原则

  1. 插件优先（Plugin-First）：所有协议驱动、存储引擎、转发通道、告警规则均以插件形式实现，核心框架不包含任何业务耦合逻辑
  2. 约定优于配置（Convention over Configuration）：提供合理默认值，零配置即可运行，高级参数可覆盖
  3. 数据零丢失（Zero Data Loss）：任何环节故障均不丢弃已采集数据，通过本地缓存与确认机制保障
  4. 松耦合高内聚（Loose Coupling / High Cohesion）：模块间通过事件总线与接口通信，无直接依赖
  5. 可观测性（Observability）：全链路日志、指标、追踪三位一体，运行状态透明可查
  6. 跨平台（Cross-Platform）：核心运行时基于跨平台技术栈，支持 Windows / Linux / 国产麒麟 / 嵌入式

3.2 核心进程模型

采集器采用多进程 + 协程混合模型：

进程 职责 说明
主控进程（Master） 全局调度、插件加载、配置管理、健康检查 单实例，守护进程
采集工作进程（Collector Worker） 执行采集任务、协议通信、数据解析 按负载水平弹性伸缩，1~N 实例
存储工作进程（Storage Worker） 数据写入、缓存管理、生命周期管理 单实例或主从
转发工作进程（Forward Worker） 数据分发、协议转码、断网缓存 单实例
告警工作进程（Alert Worker） 规则评估、告警推送、告警抑制 单实例
Web 服务进程（Web Server） 提供 UI 与 API 服务 单实例

进程间通过事件总线（基于 Unix Socket / Named Pipe 的高性能 IPC）通信，支持发布/订阅与请求/响应两种模式。
